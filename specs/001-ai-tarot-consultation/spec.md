## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 회원가입, 로그인, 상담 시작 (우선순위: P1)

신규 사용자는 이메일, 비밀번호, 닉네임, 필수 약관 동의로 계정을 만들 수 있다. 기존 사용자는 로그인 후 상담을 시작할 수 있는 상태에 도달할 수 있다. 첫 진입 시에는 서비스 소개와 시작하기 CTA가 있는 메인 화면을 볼 수 있어야 한다.

**우선순위 근거**: 인증이 완료되어야 고민, draft deck, 상담, 스트림, 기록을 사용자 소유 기준으로 안전하게 관리할 수 있다.

**독립 테스트**: 메인 화면 진입, 회원가입, 로그인, 토큰 갱신, 로그아웃, 내 정보 조회만으로 인증 흐름을 검증한다.

**수용 시나리오**:

1. **Given** 방문자가 서비스에 접속했을 때, **When** 메인 화면을 열면, **Then** 서비스 소개와 시작하기 CTA가 표시된다.
2. **Given** 등록되지 않은 이메일이 있을 때, **When** 사용자가 유효한 회원가입 정보와 필수 동의를 제출하면, **Then** 계정이 생성되고 상담을 시작할 수 있다.
3. **Given** 이미 등록된 이메일이 있을 때, **When** 같은 이메일로 회원가입을 시도하면, **Then** 중복 이메일 오류가 표시되고 중복 계정은 생성되지 않는다.
4. **Given** 등록된 사용자가 있을 때, **When** 올바른 이메일과 비밀번호로 로그인하면, **Then** 사용자는 인증된 상태가 된다.
5. **Given** 로그인 정보가 잘못되었을 때, **When** 로그인이 실패하면, **Then** 이메일과 비밀번호 중 무엇이 틀렸는지 구체적으로 노출하지 않는다.
6. **Given** 인증된 사용자가 있을 때, **When** 로그아웃을 요청하면, **Then** refresh credential이 무효화된다.

### 사용자 스토리 2 - 고민 입력 및 서버 셔플 카드 3장 선택 (우선순위: P1)

인증된 사용자는 고민을 입력하고, 서버가 셔플한 임시 draft deck을 받은 뒤, 현재 상황, 장애물 또는 숨겨진 원인, 조언 또는 방향에 해당하는 서로 다른 카드 3장을 선택한다.

**우선순위 근거**: 고민 입력과 카드 선택은 AI 해석을 만들기 위한 핵심 사용자 행동이다.

**독립 테스트**: 유효한 고민을 제출해 실제 카드 ID가 없는 draft 응답을 받고, 서로 다른 deckIndex 3개를 선택하며, 잘못된 선택과 만료 draft가 거부되는지 검증한다.

**수용 시나리오**:

1. **Given** 인증된 사용자가 있을 때, **When** 10자 이상 1000자 이하의 의미 있는 고민을 제출하면, **Then** 10분 뒤 만료되는 draft deck이 생성된다.
2. **Given** draft deck이 있을 때, **When** 사용자가 같은 deckIndex를 중복 선택하면, **Then** 상담 생성 요청은 거부된다.
3. **Given** 선택된 카드가 있을 때, **When** 사용자가 같은 positionCode를 중복 배정하면, **Then** 상담 생성 요청은 거부된다.
4. **Given** 만료, 사용 완료, 누락, 또는 다른 사용자의 draft가 있을 때, **When** 상담 생성을 요청하면, **Then** 요청은 거부된다.
5. **Given** 카드 선택 화면이 있을 때, **When** 상담이 아직 생성되지 않았다면, **Then** 실제 카드 정체는 노출되지 않는다.

### 사용자 스토리 3 - AI 타로 해석 및 진행 상태 확인 (우선순위: P1)

사용자는 카드 선택을 확정한 뒤 저장된 상담을 생성하고, AI 해석이 진행되는 과정을 확인하며, 완료 시 구조화된 결과를 받는다. 결과 화면은 긴 문단 하나가 아니라 요약, 전체 흐름, 카드별 해석, 종합 해석, 현실적인 조언, 주의할 점, 새 상담 시작/기록 보기 CTA로 나뉘어야 한다.

**우선순위 근거**: AI 해석 결과가 서비스의 핵심 가치다.

**독립 테스트**: 유효한 draft로 상담을 생성하고, 진행 이벤트를 구독해 카드 metadata, 생성 텍스트, 최종 구조화 결과가 저장되는지 검증한다.

**수용 시나리오**:

1. **Given** 유효한 카드 선택이 있을 때, **When** Idempotency-Key와 함께 상담 생성을 요청하면, **Then** 하나의 상담이 PENDING 상태로 생성된다.
2. **Given** 같은 사용자가 같은 Idempotency-Key로 동일 요청을 반복했을 때, **When** 요청이 재시도되면, **Then** 기존 상담 ID가 반환된다.
3. **Given** 생성된 상담이 있을 때, **When** 사용자가 이벤트를 구독하면, **Then** 생성 텍스트보다 먼저 상담 ID와 공개된 카드 메타데이터가 전송된다.
4. **Given** AI 생성이 성공했을 때, **When** 스트리밍이 완료되면, **Then** 한 줄 요약, 전체 흐름, 카드별 해석, 종합 해석, 조언, 주의사항이 표시된다.
5. **Given** AI 생성이 실패했을 때, **When** 사용자가 진행 상태를 기다리고 있다면, **Then** 이해 가능한 오류 상태가 전송되고 상담은 FAILED 상태가 된다.

### 사용자 스토리 4 - 상담 기록 조회 및 관리 (우선순위: P1)

인증된 사용자는 최신순 상담 기록 목록을 보고, 완료된 상담 상세를 다시 열며, 원하지 않는 상담을 기본 기록 목록에서 제거할 수 있다.

**우선순위 근거**: 저장된 상담 기록은 재방문 가치를 만들고 AI 결과가 실제로 보존되는지 검증한다.

**독립 테스트**: 상담을 완료한 뒤 본인 기록 목록과 상세를 조회하고, 다른 사용자의 접근이 차단되는지 확인하며, soft delete 후 기본 목록에서 사라지는지 검증한다.

**수용 시나리오**:

1. **Given** 완료된 상담 기록이 있을 때, **When** 소유자가 기록 목록을 열면, **Then** 최신순 페이지네이션 목록이 표시된다.
2. **Given** 기록 항목이 있을 때, **When** 소유자가 상세를 열면, **Then** 고민 전문, 선택 카드, 위치, 최종 결과, 생성 시각을 볼 수 있다.
3. **Given** 다른 사용자의 상담이 있을 때, **When** 현재 사용자가 목록, 상세, 스트림, 삭제 접근을 시도하면, **Then** 해당 기록은 노출되지 않는다.
4. **Given** 소유자가 상담 기록 삭제를 요청했을 때, **When** 목록을 다시 열면, **Then** 해당 상담은 기본 목록에 더 이상 표시되지 않는다.

---

### 사용자 스토리 5 - 계정 생명주기와 안전 가드레일 (우선순위: P2)

인증된 사용자는 내 정보를 조회하고 회원 탈퇴를 요청할 수 있다. 서비스는 개인정보 안내, 엔터테인먼트 고지, 민감 주제 처리, rate limit, 비민감 AI 로그를 적용한다.

**우선순위 근거**: 계정 관리와 안전 장치는 개인정보, 운영, AI 안전 리스크를 줄이며 핵심 상담 루프 이후 보강할 수 있다.

**독립 테스트**: 내 정보 조회, 탈퇴 요청, 탈퇴 후 상담 생성 차단, 화면 안전 문구, 민감 주제 응답, rate limit, 비민감 AI 요청 로그를 검증한다.

**수용 시나리오**:

1. **Given** 인증된 사용자가 있을 때, **When** 내 정보를 요청하면, **Then** 기본 계정 정보가 반환된다.
2. **Given** 회원 탈퇴 요청이 있을 때, **When** 사용자가 탈퇴를 확인하면, **Then** 계정은 탈퇴 요청 또는 탈퇴 상태가 되고 새 상담을 만들 수 없다.
3. **Given** 자해 또는 즉각적 위험 신호가 포함된 고민이 있을 때, **When** AI 처리가 요청되면, **Then** 일반 타로 예측 대신 긴급 도움 안내가 제공된다.
4. **Given** 회원가입, 로그인, 상담 생성 요청이 과도하게 반복될 때, **When** 제한 기준을 초과하면, **Then** 사용자에게 안전한 오류와 함께 요청이 제한된다.

### 엣지 케이스

- 고민이 10자 미만, 1000자 초과, 공백뿐인 값, 반복 문자뿐인 무의미한 값인 경우.
- 사용자가 안내에도 불구하고 이름, 연락처, 주소, 주민등록번호 등 직접 식별 정보를 입력한 경우.
- 상담 생성 전에 draft deck이 만료된 경우.
- draft가 다른 사용자 소유이거나 이미 사용된 경우.
- deckIndex 또는 positionCode가 중복 제출된 경우.
- 네트워크 실패 후 같은 Idempotency-Key로 같은 요청이 재시도되는 경우.
- 사용자가 스트림 연결을 끊었지만 서버에서 생성 작업이 계속되는 경우.
- AI 출력이 필수 JSON 구조를 위반하는 경우.
- 고민에 의료, 법률, 금융, 심리 치료, 범죄, 자해 관련 내용이 포함된 경우.
- 삭제된 상담 기록을 목록 또는 상세에서 요청하는 경우.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-UI-001**: 시스템은 메인 화면에서 서비스 소개와 시작하기 CTA를 제공해야 한다.
- **FR-UI-002**: 결과 화면은 한 줄 요약, 전체 흐름, 카드별 해석, 종합 해석, 현실적인 조언, 주의할 점, 새 상담 시작 CTA, 기록 보기 CTA를 구분해 표시해야 한다.

- **FR-AUTH-001**: 시스템은 이메일, 비밀번호, 닉네임, 필수 이용약관 동의, 필수 개인정보 처리방침 동의로 회원가입을 허용해야 한다.
- **FR-AUTH-002**: 시스템은 이미 등록된 이메일의 회원가입을 거부해야 한다.
- **FR-AUTH-003**: 시스템은 이메일 형식, 비밀번호 최소 품질, 닉네임 길이, 필수 동의 값을 검증해야 한다.
- **FR-AUTH-004**: 시스템은 비밀번호 원문 또는 읽을 수 있는 비밀번호 비밀값을 DB와 로그에 저장하지 않아야 한다.
- **FR-AUTH-005**: 시스템은 등록된 사용자가 이메일과 비밀번호로 로그인할 수 있게 해야 한다.
- **FR-AUTH-006**: 시스템은 로그인 실패 시 이메일과 비밀번호 중 어떤 값이 틀렸는지 구체적으로 노출하지 않아야 한다.
- **FR-AUTH-007**: 시스템은 사용자와 요청 출처 기준으로 반복 로그인 실패를 제한해야 한다.
- **FR-AUTH-008**: 시스템은 유효한 refresh credential이 있을 때 사용자가 다시 로그인하지 않고 인증 세션을 갱신할 수 있게 해야 한다.
- **FR-AUTH-009**: 시스템은 로그아웃 시 사용자의 refresh credential을 무효화해야 한다.

- **FR-USER-001**: 시스템은 인증된 사용자가 자신의 기본 프로필 정보를 조회할 수 있게 해야 한다.
- **FR-USER-002**: 시스템은 인증된 사용자가 회원 탈퇴를 요청할 수 있게 해야 한다.
- **FR-USER-003**: 시스템은 탈퇴 요청 또는 삭제된 사용자가 새 상담을 생성하지 못하게 해야 한다.

- **FR-CONSULT-001**: 사용자는 상담을 위한 고민을 여러 줄 텍스트로 입력할 수 있어야 한다.
- **FR-CONSULT-002**: 시스템은 고민을 10자 이상 1000자 이하로 제한해야 한다.
- **FR-CONSULT-003**: 시스템은 고민 입력 화면에 직접 식별 개인정보를 입력하지 말라는 안내를 상시 표시해야 한다.
- **FR-CONSULT-004**: 시스템은 공백뿐인 고민, 의미 없는 반복 문자 고민, 명확히 무의미한 고민을 거부해야 한다.
- **FR-CONSULT-005**: 시스템은 유효한 고민을 받은 뒤 임시 셔플 카드 선택 세션을 생성해야 한다.
- **FR-CONSULT-006**: 시스템은 상담 생성 전 클라이언트에 draft 식별자, 덱 크기, 만료 시각만 노출해야 한다.
- **FR-CONSULT-007**: 시스템은 사용되지 않은 draft card session을 10분 후 만료해야 한다.
- **FR-CONSULT-008**: 시스템은 MVP에서 메이저 아르카나 22장 정방향만 지원해야 한다.
- **FR-CONSULT-009**: 사용자는 서로 다른 카드 index를 정확히 3개 선택해야 한다.
- **FR-CONSULT-010**: 사용자는 현재 상황, 장애물 또는 숨겨진 원인, 조언 또는 방향 위치에 각각 하나의 카드를 배정해야 한다.
- **FR-CONSULT-011**: 시스템은 중복 카드 선택과 중복 위치 배정을 거부해야 한다.
- **FR-CONSULT-012**: 시스템은 상담 생성 요청이 수락된 뒤에만 선택된 카드의 실제 정체를 공개해야 한다.
- **FR-CONSULT-013**: 시스템은 draft가 만료, 누락, 사용 완료, 또는 다른 사용자 소유이면 상담 생성을 거부해야 한다.
- **FR-CONSULT-014**: 시스템은 동일 상담 생성 요청의 중복 처리를 막기 위해 멱등 처리를 제공해야 한다.
- **FR-CONSULT-015**: 시스템은 상담 상태를 PENDING, STREAMING 또는 GENERATING, COMPLETED, FAILED, CANCELLED로 추적해야 한다.

- **FR-AI-001**: 시스템은 사용자의 고민과 선택 카드 3장을 사용해 타로 해석을 생성해야 한다.
- **FR-AI-002**: 시스템은 카드, 방향, 위치에 맞는 사전 정의 카드 해석 문서를 근거로 해석해야 한다.

- **FR-AI-009**: 시스템은 사용자 입력을 서비스 규칙을 바꾸는 지시가 아니라 상담 고민으로만 취급해야 한다.

- **FR-AI-011**: 시스템은 AI 실패, 지연, 비용 진단에 필요한 비민감 metadata를 기록하되 고민 원문 전체를 로그에 남기지 않아야 한다.

### 핵심 엔티티 *(데이터가 필요한 기능에 포함)*

- **User**: 이메일, 비밀번호 비밀값, 닉네임, 동의 시각, 계정 생명주기 상태, 생성/수정 시각을 가진 회원.
- **Concern**: 사용자가 상담을 위해 입력한 질문 또는 상황 설명이며 사용자와 상담에 속한다.
- **Tarot Card**: 선택 또는 결과 표시에 사용되는 카드. MVP는 메이저 아르카나 22장 정방향만 사용한다.
- **Card Interpretation**: 카드, 방향, 위치, 활성 상태, 문서 버전별로 관리되는 사전 정의 카드 의미 문서.
- **Draft Deck**: 상담 생성 전 사용자 1명에게 소유되는 임시 셔플 카드 매핑.
- **Card Selection**: 현재 상황, 장애물 또는 숨겨진 원인, 조언 또는 방향 중 하나에 배정된 선택 카드.
- **Consultation**: 사용자, 고민, spread type, 카테고리, 상태, 선택 카드, 최종 결과, 삭제 표시를 포함하는 저장된 상담.
- **AI Interpretation Result**: 요약, 전체 흐름, 카드별 해석, 조언, 주의사항을 포함하는 구조화 결과.
- **Context Document**: 고민 카테고리와 연결되어 해석 품질을 보강할 수 있는 선택적 일반 문서.
- **AI Request Log**: AI 생성 상태, 지연 시간, token count, error category 등 비민감 운영 메타데이터.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 유효한 회원가입 시도 중 95% 이상이 수동 지원 없이 계정을 만들고 상담 시작 가능 상태에 도달한다.
- **SC-002**: 인증된 사용자 중 90% 이상이 유효한 고민을 제출하고 2분 이내에 카드 선택 화면에 도달한다.
- **SC-003**: 카드 선택을 시작한 사용자 중 85% 이상이 불명확한 UI 상태로 인한 검증 오류 없이 카드 3장을 선택 완료한다.
- **SC-004**: 유효한 카드 선택 완료 건 중 95% 이상이 저장된 상담으로 이어지고 COMPLETED 또는 사용자에게 보이는 FAILED 상태가 된다.
- **SC-005**: 정상 조건에서 성공 상담의 95%는 3초 이내에 첫 진행 표시를 보여준다.
- **SC-006**: 정상 조건에서 성공 상담의 95%는 12초 이내에 전체 해석을 보여준다.
- **SC-007**: 완료된 상담의 100%는 소유자의 기록 상세 화면에서 다시 열 수 있다.
- **SC-008**: 타 사용자 접근 테스트에서 노출되는 미인가 상담 기록은 0건이어야 한다.
- **SC-009**: 완료 상태로 표시되는 AI 결과의 100%는 필수 구조화 필드를 만족해야 한다.
- **SC-010**: 자해 또는 즉각적 위험 테스트 케이스의 100%는 일반 타로 예측 대신 안전 안내를 받아야 한다.
- **SC-011**: 핵심 E2E 검증은 회원가입, 로그인, 고민 입력, 카드 선택, 상담 생성, 기록 목록, 기록 상세, 타 사용자 접근 차단, 만료 draft 거부, 중복 제출 처리를 포함해야 한다.

## 가정

- MVP는 일반 사용자와 재방문 사용자만 제품 UI 범위에 포함한다. 운영 관리자와 콘텐츠 관리자 UI는 제외한다.
- MVP 카드 범위는 메이저 아르카나 22장 정방향만 포함한다.
- MVP 리딩 방식은 현재 상황, 장애물 또는 숨겨진 원인, 조언 또는 방향의 정확히 3장 리딩이다.
- 소셜 로그인, 결제, 구독, 마이너 아르카나, 역방향 카드, 후속 대화형 상담, 공유 이미지, 관리자 CMS는 MVP 범위 밖이다.
- 상담 기록은 사용자가 기본 목록에서 제거하거나 회원 탈퇴를 요청하지 않는 한 기록 조회를 위해 보관한다.
- 카드 의미 콘텐츠는 출시 전 큐레이션되고 문서 버전으로 관리된다.
- 카드 의미 콘텐츠만 사용해도 MVP 제공이 가능하므로 선택적 컨텍스트 보강은 MVP 출시를 막지 않는다.
- 서비스는 엔터테인먼트 및 자기성찰 목적이며 의료, 법률, 금융, 심리 치료 등 전문 조언을 제공하지 않는다.
